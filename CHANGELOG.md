# Changelog

## Unreleased

- **Added: Translation review** per language (Settings → Languages, a checkbox below each target language's combo box, off by default): translations into a language with *Translation review* ticked go through Supertext's review service (Supertext Localization Review), where your colleagues and Supertext linguists correct them on the online store with a Chrome extension; corrections come back into Shopify with the next translation (with *Overwrite existing translations*), and texts translated before keep their (reviewed) wording. Same API key, billing, languages and messages; other languages keep going directly to Supertext. Server variable `SUPERTEXT_REVIEW_URL` (defaults to Supertext's review service; empty turns review off for every shop). Database migration `20261019000000_translation_review`. All four interface languages.
- **Added: Export for translation (XLIFF 1.2 or HTML) and import of translated files; Supertext SDK 0.5.0.** On the Translate page, below the translate button: export the selected item for a translator, a translation tool or Supertext's web app (XLIFF with one or more languages, HTML with one), and import the translated file (up to 10 MB). The import writes the translations like Supertext's, keeps current translations unless *Overwrite existing translations*, skips texts whose source changed since the export unless asked, and shows a summary per item and language. All four interface languages. Bundled Supertext SDK updated to 0.5.0 (commit `a47ca07`).
- **Changed: Settings → Languages has a combo box per shop language** (Polaris select with Supertext's languages as *Name (code)*, names in the admin language), preselected with Supertext's suggestion. **Languages nobody mapped now translate with Supertext's default** instead of being blocked: `de` → `de-DE`, `en` → `en-US`, `fr` → `fr-FR`, `it` → `it-IT`, `pt` → `pt-PT`, `zh-CN` → `zh-Hans`, `zh-TW` → `zh-Hant`, `es-ES` → `es`, … Only languages without a default (`en-IE`, `de-LI`, `gsw`, …) show *— choose —* and *No Supertext language* and stay blocked until chosen. Saved mappings stay as they are. Bundled Supertext SDK updated to 0.4.0 (commit `6aaad33`).
- The public pages outside the Shopify admin (landing page, login page, privacy policy) now have Supertext's look: deep-green header with the Supertext logo, warm off-white background, mint buttons, Inter bundled with the app. New favicon (the Supertext S). The pages inside the Shopify admin keep Shopify's own look.
- Changed: version reports and the API key check result now use Supertext Plugin Health 0.1.0 (bundled in `vendor/supertext-plugin-health`); bundled Supertext SDK updated to 0.3.0 (commit `f7bd414`). No change for shops: settings and stored state stay as they are.
- **Changed: no more guessed language regions.** Settings → Languages now maps each shop language to a Supertext language from Supertext's own list (with a picker), and shows what each language is sent as or *Not mapped*. Shopify codes that are Supertext codes (`es`, `nl`, `pt-BR`, …) work as they are; `de`, `fr`, `en`, `it` need a mapping (e.g. `de` → `de-CH`), there is no default `de-DE` any more. **Shops that relied on the old defaults must set these once.** An unmapped language sends nothing to Supertext and shows *"de" has no Supertext language yet* (all four interface languages); the translate page disables unmapped languages. Codes Supertext doesn't offer aren't saved.
- Formal/informal is sent only for languages that offer it (not for English, Romansh, Albanian, Serbian, Swiss German dialect); the settings page notes it. New message for *unsupported_feature*.
- Added: automatic API key check after every save and with the new **Test connection** button (*API key check* box with the last result and its time). Messages for invalid or missing keys link to the Supertext sign-up and API key pages.
- Added: **Send version information to Supertext** (on by default): the shop's myshopify.com address, the app, Shopify API and runtime versions and the key check result go to the Supertext Commando Center when the settings are saved and after updates. No content, key or personal data. `SUPERTEXT_VERSION_REPORTS=0` turns it off on the server. The privacy policy says so. Database migration `20261014000000_commando_center`.
- The *Save and test connection* button is replaced by *Save* (which checks the key) and *Test connection*.
- Supertext SDK updated to 0.2.1 (API in the SDK's `v1` namespace; `scripts/vendor-sdk.sh` copies its folders).

- Fixed: a target language Supertext doesn't know is now reported as an unsupported language pair, pointing to Settings → Languages (was: *The requested Supertext resource was not found*). Supertext SDK updated to commit aba02dd.
- The app now talks to Supertext through the Supertext SDK for TypeScript (version 0.1.0, bundled in `vendor/supertext-sdk/` until it is on npm), instead of its own client. Same behaviour for merchants; requests now identify the app (`Shopify-Supertext-Translation/<version>`).
- The app server now runs in the EU (Amsterdam), like its database; the privacy policy says so.
- Added: German, French and Italian interface. The app follows the Shopify admin language (`locale` parameter), English otherwise; errors from Supertext and Shopify are shown in that language too.
- The *Authentication failed* message now also links to the Supertext sign-up page.
- Supertext API keys are stored encrypted (AES-256-GCM). Keys saved earlier are encrypted automatically the next time they are used. If a stored key can't be read, Settings asks to enter it again.
- Translations interrupted by an app update are now marked *Interrupted by an app update* instead of staying *Translating…* forever.
- Public privacy policy page at `/privacy`.
- The start page no longer asks for a shop domain (App Store rule 2.3.1); installs start from Shopify.
- docs/APP_STORE.md: submission checklist, listing texts, reviewer instructions and screencast script.
- A **Settings** link at the top of the translate page and next to the languages, so Settings is easy to find on a phone, where the admin doesn't show the app's menu.
- Settings → Languages: the Supertext code for each shop language, pre-filled with a regional default (de → de-DE, fr → fr-FR, en → en-US, …) and editable (e.g. de-CH). Fixes translations failing with *INVALID_LANGUAGE_PAIR*, because Supertext needs a region for the target language and Shopify uses bare codes like "de". The translate page shows the code each language is sent with.
- A language Supertext refuses is now reported once per run, with a message pointing to Settings → Languages, instead of once per item.
- First version: an embedded Shopify app, **Apps → Supertext Translation**, made from Shopify's React Router template.
- Translate page: pick products, collections, pages, blog posts or blogs and the target languages, then *Translate with Supertext*. Runs in the background with progress and per-item errors under *Recent translations*.
- Translates text and HTML fields (titles, descriptions, SEO title and description, …) and writes them to Shopify's translation store with `translationsRegister`; URL handles are left alone. Existing translations are kept unless *Overwrite existing translations* is ticked; outdated ones are always translated again.
- Settings page: Supertext API key (with links to create an account and generate the key), form of address, connection test, and the app version linked to its GitHub release.
- Supertext client shared with the other plugins: retries on HTTP 429, accepts the key with or without the `Supertext-Auth-Key ` prefix, splits very large items into several documents.
- Privacy webhooks (customer data request, customer redact, shop redact).
- Dockerfile and Railway configuration; the app creates its own database on the shared Postgres server on start.
- Installation guide, user guide and developer guide; unit tests against a stand-in Shopify and Supertext.
